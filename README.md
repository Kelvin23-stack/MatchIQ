# MatchIQ (single source file)

All front-end code is in **`main.jsx`** (generated by bundling the multi-file project; each original file starts at a `// FileName` marker). The files that cannot be merged are: `api/football.js` (Vercel only runs functions from a folder named exactly `api`), `package.json`, `index.html`, `index.css`, `vite.config.js`, `tailwind.config.js`, `postcss.config.js` and the two stadium images.

```
npm install
npm run dev
npm run build
```

## Live football data setup (Highlightly)

All MatchIQ football data (fixtures, scores, lineups, events, statistics, standings, players) comes from the **Highlightly Football API** through a small server function, so the secret key never reaches the browser. There is no demo mode and no built-in sample football data.

| Piece | File | Runs on |
|---|---|---|
| Server proxy (holds the key, validates requests, caches, merges pages) | `api/football.js` | Server only (Vercel Function, or the Vite dev middleware) |
| Browser data layer (cache, de-duplication, error handling) | `footballApi.js`, `dataMode.js` | Browser |
| Provider response -> MatchIQ structures | `liveData.js` | Browser |
| Provider match -> UI match adapter, multi-day hooks | `liveMatch.js` | Browser |
| Live screens | `LiveMatches.jsx`, `LiveMatchPage.jsx`, `LivePlayers.jsx`, `LiveBits.jsx` | Browser |

The endpoint path stays `/api/football`. Only the provider behind it changed.

## 1. Key and plan
Create an account at https://highlightly.net, subscribe to the **Football API** and copy your key. Do not paste it into any source file. This app uses the **direct Highlightly** base URL `https://soccer.highlightly.net` with the header `x-rapidapi-key` (the `x-rapidapi-host` header is only for RapidAPI and is not sent). Check your plan's daily quota and restrictions in the Highlightly dashboard; the Basic/Free plan has restrictions.

## 2. Find your competition ids
Ids are never hard-coded. Look them up once and put them in `HIGHLIGHTLY_LEAGUES`:
```
export HL_KEY="your_key"
curl -s "https://soccer.highlightly.net/leagues?leagueName=Premier%20League&countryName=England" -H "x-rapidapi-key: $HL_KEY"
```
Repeat for La Liga (Spain), Bundesliga (Germany), Serie A (Italy), Ligue 1 (France) and UEFA Champions League. Use the `id` of each result. Competition names and logos are then read from the API (`/leagues/{id}`), and users switch between them with the chips in Match Centre. The first id is the default.

## 3. Local development
```
npm install
cp .env.example .env     # set HIGHLIGHTLY_API_KEY and HIGHLIGHTLY_LEAGUES
npm run dev
```
`.env` is git-ignored and read by the Vite **server process** only. Open **Settings -> Data source -> Test connection** to see the configured competitions, your plan tier and the requests left today.

## 4. Deploy on Vercel
1. Put the project in a GitHub repository. The repo root must contain `package.json`, `index.html`, `vite.config.js` and the folder `api/` with `football.js` inside (exactly this name and place; Vercel only detects functions there). Everything else is flat in the same folder.
   - Uploading through the GitHub website: drag the files in, then use **Add file -> Create new file**, type `api/football.js` (the slash creates the folder) and paste the file contents.
2. In Vercel choose **Add New -> Project**, import the repo. The framework is detected as Vite (build `vite build`, output `dist`). No `vercel.json` is needed.
3. Before the first deploy, open **Environment Variables** and add (Production and Preview): `HIGHLIGHTLY_API_KEY` (mark Sensitive), `HIGHLIGHTLY_LEAGUES` (comma-separated numeric ids, first = default), and optionally `HIGHLIGHTLY_SEASON`. Do not add any `VITE_` variable for the key.
4. Deploy. Variables are only read by a new deployment, so after changing one you must redeploy.
5. Check `https://YOUR-APP.vercel.app/api/football?action=config`. It should show `"configured":true` and your league ids. Then open the app and use Settings -> Data source -> Test connection.
The proxy keeps every request under 10 seconds (it stops merging extra pages if the provider is slow), so it fits even the older Hobby function limit.

## 5. Endpoints used (all through `/api/football?action=...`)
| action | Highlightly endpoint | Used for |
|---|---|---|
| fixtures | `GET /matches?leagueId&date[&timezone&season]` | Today, Yesterday, Live, Upcoming, Finished, date picker. Pages are merged server-side until `pagination.totalCount` is reached (max 5 pages). |
| fixture | `GET /matches/{id}` | Match page: venue, referee, **events and team statistics (inline)**, top players |
| lineups | `GET /lineups/{matchId}` | Starting XI, formation, substitutes |
| standings | `GET /standings?leagueId&season` | League table |
| leagues | `GET /leagues/{id}` | Competition name, logo, country |
| players | `GET /players?name` | Player search |
| player | `GET /players/{id}` | Profile |
| playerStats | `GET /players/{id}/statistics` | Per-competition and per-club statistics |
| status | `GET /leagues?limit=1` | Plan tier and quota headers (Highlightly has no status endpoint) |

Anything else returns 400. All parameters are validated server-side; league ids must be in `HIGHLIGHTLY_LEAGUES`.

## 6. How the quota is protected
- **Highlightly's `/matches` takes a single date**, so there is no "live" or "next N" query. *Live* filters today's matches by state (refreshed about once a minute while that tab is open and visible). *Upcoming* and *Finished* load 3 days at a time with a "Show 3 more days" button. The Overview and Landing page scan forward day by day only until enough matches are found (max 7 requests, each cached for an hour).
- Server TTLs (`Cache-Control: s-maxage`): live 45 s, today 5 min, future dates 1 h, past dates 6 h, match detail 60 s (6 h once finished), lineups 5 min (6 h once finished), standings 1 h, leagues 24 h, player search 30 min, player profile and statistics 24 h.
- Per-instance memory cache on the server, plus a browser cache (memory + sessionStorage) with in-flight de-duplication.
- Failures are not retried automatically. After a rate-limit error the browser pauses for a minute (10 minutes after a daily-quota error). Cached data shown after a failure is labelled "cached".
- The banner above live lists shows the requests left today from the provider's `x-ratelimit-requests-remaining` header, and any plan notice returned in the response's `plan.message`.

## 7. What Highlightly does not provide (so MatchIQ does not show it)
- No per-match player ratings and no full per-match player table. The Player Stats tab shows the provider's **top players** for the match with their highlighted statistics.
- No squad lists, no top-scorer or top-assist lists, no "form" string in standings. Player Discover is a name search (3+ letters). Goal difference is computed from goals for/against.
- Team country and competition are not part of `/teams`; team logos and names come from the match data.
- Shirt numbers appear in match lineups only, not on player profiles. Venue and referee exist only on the match detail, not in lists.
- Lineups are published from about 40 minutes before kickoff; before that the lineup tab shows an unavailable state.

## 8. Verify the key is not exposed
1. `npm run build`, then `grep -r "YOUR_ACTUAL_KEY" dist` must print nothing; also `grep -ri "x-rapidapi-key" dist` must print nothing.
2. In DevTools -> Network, requests go to `/api/football?...` only. Nothing is sent to `soccer.highlightly.net` from the browser.
3. `git log -p | grep "YOUR_ACTUAL_KEY"` prints nothing and `.env` is in `.gitignore`.
If a key was ever committed or pasted somewhere public, rotate it in the Highlightly dashboard.

## 9. Still to verify with a real key
The proxy and normalisers follow the Highlightly OpenAPI spec (Football API v8.2.7) and are tested against payloads validated against that spec, **not against live responses**. Confirm on your first real responses:
- Season numbering (is `2026` the 2026/27 season?). Override it in Settings if standings come back empty.
- Statistic units: values (e.g. possession, shot accuracy) are shown exactly as returned; the spec's example for "Shots accuracy" is `0.62`.
- Substitution events: the app shows `player / substituted` without claiming which player came on.
- Lineup pitch orientation (home left-to-right) and whether `initialLineup` arrives as rows or as a flat list (both are handled).
- Which endpoints your plan includes (a 403 is shown with the provider's message).

## 10. Phase 1 scope notes
Points, accuracy, streak, XP, badges, leaderboards, community users/posts/chats and the Landing page marketing numbers are placeholders until Phase 2. They are not football data. Predictions are stored in the browser by real match id.
